Using the knowledge base and my Business File (§6 funnel map, §7
lead capture, §1 lead sources), map the machine. Do not write any
copy yet.

━━ THE UNDIRECTED INVENTORY ━━

Define every conversion point in my process — every place a yes
or a no happens — without me steering you first. Include the ones
I'd never think to automate (watched the video or didn't; booked
but hasn't confirmed; paid but hasn't onboarded; finished but
never referred; cold for 90+ days). List them in funnel order.

Then ask me: "What did I miss, and which of these matter most?"

━━ THE CAMPAIGN MAP ━━

For each conversion point that gets a campaign:

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
| # | CAMPAIGN NAME | CONVERSION POINT | ENTRY CONDITION (tag) | EXIT CONDITION (tag) | CHANNELS | PRIORITY |
|---|---|---|---|---|---|---|
...
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Rules: entry and exit are tags you name now, in a convention we'll
fix in Prompt 3. Channels default to email; add SMS or ad
audiences only where my file says I have them. Priority ranks by
where my funnel bleeds most, from "where people fall off."

━━ FRESH, REACTIVATION, OR BOTH ━━

From my list numbers: tell me whether this build is a fresh-lead
machine, a reactivation, or both, and what that changes. If
reactivation: add the list-audit step to the front of everything
and the sunset campaign to the back.

━━ THE SIZE OF THE BUILD ━━

Campaign count, estimated message count, and an honest build-time
range for an agent and for a human. Then ask me to confirm the
map or cut it. Three to six campaigns is a strong first machine;
ten is a mature one.

PROMPT 2 — THE BELIEF MAP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

---

Now the psychology. Read §2 (pains, identity monologue, switching
forces, objections, sourced language), §3 (promise, guarantee,
urgency), and §4 (villain, differentiator).

━━ THE FIVE BELIEFS ━━

State the five beliefs a prospect must hold to buy my core offer,
in the knowledge-base shape:
   1. surface pain — "this is solvable"
   2. identity pain — "I am not the problem"
   3. reframe — "the real cause was hidden"
   4. proof — "this person has done it"
   5. anticipation — "the next step is obvious"
Each in one sentence, in my prospect's words where §2 has them.
Then ask me to confirm or rewrite, one belief at a time. These are
mine; you don't proceed on an unconfirmed belief.

━━ AWARENESS ENTRY LEVELS ━━

For each campaign in the map, the Schwartz level a contact is at
when they ENTER it, and the level the campaign should leave them
at. Flag any campaign written for the wrong level (an invite to a
problem-aware contact; a disarm to a most-aware one).

━━ BELIEF PER CAMPAIGN ━━

For each campaign: the ONE belief it installs (from the five, or a
sub-belief of one), and which stages of the seven-stage model it
runs. A short campaign at a late conversion point may run only
Authorize → Invite. The reactivation sequence runs all seven.

━━ THE CORE BELIEF ━━

The one belief the whole machine drives toward, in one sentence.
Everything else is a step toward it.

━━ THE STORY BANK ━━

From my file and what I've told you, the raw material for the
stories: the mirror moment (Identify), the misdiagnosis
(Reframe), the discovery (Illuminate), the origin or case study
(Authorize). Where the file is thin, ask me one question at a
time for the specific detail; hyper-specific detail is what makes
these work. Never invent a case study.

PROMPT 3 — TAG ARCHITECTURE AND CONTROL LOGIC
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

---

Build the scaffolding. This is mechanical; say so, and say which
model tier it needs.

━━ THE TAG ARCHITECTURE ━━

Every tag the machine needs, by family, with ONE naming convention
I can read at a glance: lowercase kebab-case with a family prefix
(`src-bootcamp`, `status-new-lead`, `age-`, `eng-`,
`cmp-[name]-entry / -active / -done / -exited`). Never mix styles
(`Status: New Lead` next to `status-new-lead` is how a real build
ended up with two conventions):

   SOURCE TAGS — one per lead source in §1/§6/§7
   STATUS TAGS — the chain of yeses as states
   LEAD-AGE AND ROI TAGS
   ENGAGEMENT TAGS — under 30 · 31–60 · 61–90 · over 90
   CAMPAIGN TAGS — entry · active · done · exited-early, per campaign
   REMOVAL SCHEDULE — which tags expire, when, and what removes them

Master tag list at the end, counted. If my CRM already has tags,
map mine onto these and tell me which to keep, rename, or retire.

━━ THE MASTER CONTROLLER ━━

The switching station, as a numbered workflow: trigger (the
`decision-machine-start` tag), the decision diamond per campaign in
priority order (checks the campaign's `done` tag), the enroll
action, the return-to-start (re-apply the start tag on exit).
State it so an agent could build it and so I could draw it.

If this is my first build, say so and offer the stand-in: one
linear sequence on the first conversion point with one entry tag
and one exit tag ("the sequence is the Decision Machine for now").
The controller is the target; the stand-in is a legitimate v1.

━━ THE ENGAGEMENT TRACKER ━━

The automation that re-buckets contacts on open, click, and reply,
and applies the engagement tags. Plus the rule for what an
"engaged" reply does (stops automation for a human answer).

━━ THE STAGGER (only if my list is over ~10,000) ━━

The engagement-gated delays and the 1–10 random segment for
broadcasts. If my list is smaller, one line: not needed yet, and
the size at which it is.

━━ THE CONTROL LOGIC CHECK ━━

Walk one contact through the machine from entry to core-offer
purchase, and one from entry to sunset, naming every tag applied
and removed. Any point where a contact could get stuck, be
double-enrolled, or be released into nothing: flag it and fix it.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Run this once per campaign, in priority order. Creative work;

Write the messages for [CAMPAIGN NAME]. Belief: [from Prompt 2].
Stages: [from Prompt 2]. Voice: [my samples / my file].

━━ THE SEQUENCE PLAN ━━

Before writing: one line per message — stage, the one belief
shift, the story it uses from the story bank, the open loop it
opens or closes, the promotion rule for that stage, and the
send-day relative to entry (a proposal; my cadence wins). Ask me
to confirm the plan.

━━ ONE MESSAGE PER OUTPUT ━━

Then write message 1 only. Wait for my review. Then message 2.
Never two in one output. Each message:
   SUBJECT: [Disarm may use first name only; use it sparingly]
   BODY: written to one person, in narrative, hyper-specific
      detail, one belief, the loop opened or closed, and the
      promotion rule for its stage obeyed absolutely
   NOTES: the belief installed · loop status · which lines use
      §2 sourced language vs hypothesis language · the CTA if any

Stylist rule: Disarm through Authorize in narrative voice. The
Invite in Kern's voice unless I say otherwise. If I ask for a
click, Halbert.

━━ THE SUNSET (reactivation, or any campaign that ends in silence) ━━

The honest removal email: what happens, why, the one button that
keeps them, no guilt. Position it last, never early.

━━ THE CAMPAIGN CHECK ━━

After the last message: does every message serve the core belief?
Is there any promotion before Authorize? Is any belief stacked?
Fix, then mark the campaign "written".

━━ THE CRM BUILD MAP ━━

For my platform, in build order, as instructions an agent can
execute in one pass and I could follow by hand:
   1. TAGS — create the master list (mechanical; cheap model)
   2. CUSTOM FIELDS — engagement bucket, segment 1–10, last-engaged
   3. WORKFLOWS — the master controller, the engagement tracker,
      one workflow per campaign with its entry condition, messages,
      waits, and exit tag; the stagger if applicable
   4. MESSAGES — load each written message into its step
   5. SMART LISTS / SEGMENTS — engaged, dormant, sunset-pending
State where my CRM's API stops and the agent must use the UI, and
what to save as it goes. One workflow per instruction: a whole
system in one prompt fails. If an agent is building it, give me the
exact instruction to hand it, including "no creative in this pass."

━━ THE VERIFICATION CHECKLIST ━━

The pass I run before anything goes live, as checkboxes:
   [ ] every campaign: entry tag correct
   [ ] every campaign: exit tag applied at the end
   [ ] no campaign releases a contact into nothing
   [ ] the master controller checks the right `done` tag
   [ ] engagement tracker stops automation on a human reply
   [ ] every message loaded matches the written version
   [ ] links resolve; the invite points at the offer link
   [ ] SPF / DKIM / DMARC verified · one-click unsubscribe on
   [ ] test contact walked end to end; test contact sunset
   [ ] launch test: my own email submitted → delivery email lands
       within 2 minutes → sequence queued → test booking → the
       exit tag removes me from the sequence → every page checked
       at phone width
   [ ] send ledger or log exists; a recovery plan for a bad send
"Don't trust, verify" — I check the tags myself.

━━ THE LAUNCH PLAN ━━

Day 1 list verification (and warm-up if cold) · Day 2 build ·
Day 3 verification pass · Day 4 first sends to the engaged
bucket · Day 5–7 open the rest. For a fresh-lead machine, the
first live entry point and how I'll watch it for a week.

━━ THE MAINTENANCE RULE ━━

What triggers a change: a new conversion point, a new offer, a
belief that stopped landing (reply and click data), a complaint
rate over threshold. Who owns the machine. The quarterly
re-inventory.

━━ THE §16 UPDATE ━━

Emit the Follow-Up Engine section for my Business File: the five
beliefs, the campaign map (name · entry · exit · belief · status),
the awareness entry level, the tag architecture document name,
build status (tags · fields · workflows · messages: built ·
verified), engagement tracker and stagger status, reactivation
line, deliverability line, metrics to watch, and the Pack link.

━━ WHAT TO DO BEFORE THE FIRST SEND ━━

The five actions, ordered by time, with the verification pass as
number one.
