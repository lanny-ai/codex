# Pages on Demand — Publishing a Page to a Branded Domain

Reconstructed from the Build Room session of 2026-07-08 (host Lanny Morton, AI Momentum Labs). Quotations are Lanny's words with timestamps. *(inference)* marks a reconstruction the transcript does not state. This is a deployment reference for the offer page and lead capture skills: how a finished HTML page gets onto the member's own domain without a page builder.

## What it is and why it matters

"Basically using an API connection to create pages on the fly, however you want. And I can tell you that I'm not building pages with page builders anymore at all. Like, zero." [00:02:46]

"The whole point of this is to put a page on a branded domain that's yours. Not a claude.ai forward slash blahdy blah, or a netlify dot such and such. Without that, this whole process to me is worthless." [00:24:53–00:25:02]

"Just know that this is a one-time setup. And then once you've done this one time, you essentially have a little magic wand." [00:24:06] "Once you do this once, you'll never have to do it again, unless you get a new domain." [02:22:46]

The proof story: seventy-five personalised dossier pages plus an index page and a QR code, generated and published from a phone in about five minutes [00:04:22–00:06:22].

## What worked on the call

Two paths were attempted and stalled (Cloudflare through the dashboard, Netlify through its API). The path that worked, and the default here: drag the Build Room Pages zip into Claude Code, let it walk you through a Cloudflare Pages project and an "Edit Cloudflare Workers" API token, and ask it to publish a test page to your subdomain [01:44:26–02:01:56]. "I probably should have started here." [01:45:20]

Pages are plain HTML generated by the AI, styled by the design agent in the pack. No framework. GoHighLevel cannot receive pages through its API: "You cannot push pages onto GHL. It doesn't connect that way." [01:41:55]

## Prerequisites

- A domain you own. "You need a domain, period." [00:25:27] Cloudflare "sells domains at cost, they don't mark them up" [00:25:45]; about $10. Keep it short; put a core product on a root domain, not a subdomain.
- A free Cloudflare account with the domain added (nameservers switched at the registrar). "It's literally copy and paste. The hardest part is just finding where you copy and paste." [00:26:52]
- A subdomain for pages, for example `pages.yourdomain.com` or `grow.yourdomain.com`. A subdomain already serving an app cannot be reused.
- Claude Code (or Cowork) with the Build Room Pages zip, and a project folder with a `.env` file.

## The runbook

### Phase A — one-time setup

1. **Domain on Cloudflare.** If it isn't: Cloudflare → Add a domain → Free plan → copy the two nameservers into your registrar's custom DNS → wait for propagation.
2. **Project folder and `.env`.** Ask any assistant: "I want you to create a .env file, and just make it so I can copy and paste the API keys in. Format it for me." [00:42:20] Keys go between the quotes. One `.env` folder for everything; if Claude can't find it, "go find my .env file." [00:50:57]
3. **Install the pages skill.** Drag the Build Room Pages zip into Claude Code and say: "I want the ability to create pages on the fly. Go ahead and install this, and let me know what API keys you need for me to be able to build pages on the fly." [01:44:45] It installs the skill and asks whether you need the Cloudflare setup or just the keys.
4. **Answer "Cloudflare setup."** Confirm you own a domain and have an account; name the subdomain [01:47:13–01:47:59].
5. **Create the Pages project with a placeholder.** Cloudflare → Workers & Pages → Create → direct upload → an empty file is enough [01:48:53–01:50:40]. This is the step that was skipped and turned out to be required.
6. **Connect the custom domain.** On the project: Connect a custom domain → your subdomain [01:50:47–01:51:45]. *(inference)* Cloudflare adds the CNAME itself when the zone is already on Cloudflare; if DNS lives elsewhere, add a CNAME to `<project>.pages.dev` by hand.
7. **Create the API token.** Profile icon → My Profile → API Tokens → Create Token → the **"Edit Cloudflare Workers"** template → your account → All zones from an account → Continue to summary → Create Token [01:52:38–01:54:40]. Copy the token **and** your Account ID [01:54:06].
8. **Test it.** Run the curl command Claude Code gives you; expect "Token is valid and active" [01:54:50]. Paste the result back.
9. **Store the token in `.env`**, never in the chat. *(inference)* Variable names such as `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` come from the skill; read what it expects. Then: "pick this up and connect the CLI." [00:38:33]
10. **Publish a test page.** "I just want you to create a page and see if it worked. The URL is <your subdomain>." [01:56:03] → "It worked. So that process does work." [01:57:47]

### Phase B — every page after that

11. Describe the page and say "put it on a branded page for me" [02:02:33], giving the source content (the offer page copy, the lead magnet and landing page copy) and any style direction. The design agent handles look and feel. Index pages, per-person pages, and QR codes can be requested in the same instruction.
12. *(inference)* The skill writes static HTML, deploys it to the Pages project through the Cloudflare API, and returns `https://<subdomain>/<slug>`. To update, regenerate and redeploy to the same slug.

### Netlify alternative (partial on the call)

Free account → User settings → Applications → New access token (short-lived; Lanny made a 7-day one) → create a site through the API (the response's `id` is the site ID) → publish → Domain management → add your subdomain → TXT verification if asked → CNAME to `<site>.netlify.app`. The CNAME "didn't work" on the call [01:22:41]; treat this path as unverified.

## Forms and opt-ins: the open design decision

This session did not cover wiring a form on a self-hosted page to a CRM, and GHL cannot host the page for you. Until the member has a verified path, the safe options *(inference)* are:

- Embed a GoHighLevel form on the self-hosted page (GHL provides an embed snippet), so the opt-in and the delivery automation stay inside GHL as the Lead Capture skill's build steps describe.
- Or keep the opt-in page itself in GHL and use the branded self-hosted page for the offer page and any content pages.

Say which you chose in §7's landing page line, and never leave a form on a self-hosted page that posts nowhere.

## Security rules, in Lanny's words

- "The reason you use a .env file is so you don't expose your keys to the LLM models. The .env file sits on your local computer, so it's not on the internet." [01:09:42–01:10:09]
- "If you expose your API key to Claude or ChatGPT, you should really recycle it. Just regenerate the key, put a new one in." [01:10:20] He did this live after pasting a key on the recording: "somebody could get that key, and all of a sudden they got access to my Cloudflare, and that's a very bad thing." [01:20:57]
- Rotate keys at least every 90 days [01:11:39]. Scope tokens as narrowly as the task allows [00:33:45]. Use short-lived tokens for demos.
- When stuck: "take a screenshot of the whole page and say, I can't find the button." [01:58:41]

## Costs and limits stated

Cloudflare account free; domain at cost; Netlify has a free tier. Both hosts push you to a paid tier around a hundred thousand hits [01:29:54]. Free-tier APIs suggested for other connections: Groq, Tavily, Firecrawl, Deepgram, Telegram Bot [00:45:08–00:46:11].
