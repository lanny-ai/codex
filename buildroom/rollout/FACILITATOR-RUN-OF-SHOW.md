# Build Room OS — Launch Session Run of Show

**Length:** 60 minutes live · **Format:** screen share, one live demo, members install alongside
**Send before the session:** the install bundle ZIP. **Ask members to have:** Claude Cowork open, their old Build Room documents handy (ICA, offer doc — whatever they have).

## The one message of the session

> "You will never re-explain your business to Claude again."

Everything in the hour serves that sentence. Don't teach the architecture — show the moment a session skips the interview.

## Run of show

### 00:00 — Cold open: the problem (5 min)
- Ask: "How many of you have re-explained your business to Claude this month?" (Every hand goes up.)
- Name the old pain honestly: every session started from zero, or from "go find your Week 1 doc and paste it."
- The reveal: one file now carries everything. Every session reads it first and updates it last.

### 00:05 — The Business File, shown not explained (7 min)
- Screen-share a filled example Business File (build one for a fictional member beforehand — takes one ICA session).
- Scroll it top to bottom slowly. Point at three things only:
  - the **section statuses** ("complete / provisional / not started — your file knows where you are"),
  - the **verbatim language bank** ("your clients' exact words, on tap for every piece of copy"),
  - the **session log** ("your build history, with your own ratings").
- Say the rules once: bring it every time · save the updated copy · your hand edits always win.

### 00:12 — Install together (8 min)
- Screen-share `BuildRoom_OS_Quick_Start.html`.
- Everyone uploads all seven `.skill` files now (Settings → Skills → Upload Skill). Order doesn't matter.
- Members who had the old Lead Capture skill: the new one replaces it, same install step.
- While uploads run, preview the session table — what each skill builds and its trigger phrase.

### 00:20 — LIVE DEMO 1: the navigator (8 min)
- Fresh Cowork session, live: **"I'm new to the Build Room — set me up."**
- Let it run the snapshot intake (have your fictional business's answers ready — keep it brisk).
- Show the file it emits at the end. Save it on screen — model the habit.
- Then ask it: **"What should I work on next?"** — show the progress view and the single recommendation.

### 00:28 — LIVE DEMO 2: the compounding moment (12 min)
**This is the whole session. Do not cut it.**
- Open a new session with your *pre-built, completed* example file. Say: **"Write my offer page."**
- The skill reads the file and comes back with, in effect: "Here's what I'm working from" — avatar, offer, positioning, all pre-filled — and asks only for social proof.
- Pause the demo right there. Point at the screen: **"I answered zero questions about my business. It already knew. That's the file working."**
- Let it draft the headline section, then stop — the point is made; the full build is homework.

### 00:40 — Members with history: the migration path (5 min)
- "Already did ICA or offer work the old way? You don't start over."
- Show it: paste an old ICA document into the navigator with "set me up with what I have" — it builds the file from existing work.

### 00:45 — Q&A + first assignment (15 min)
- **The assignment:** before next week, run the navigator, then complete ONE session (new members: Ideal Client Avatar; members with a complete foundation: Funnel Map). Bring your updated Business File's session log to next week's call.
- Q&A. Likely questions:
  - *"Where does the file live?"* — Anywhere they keep documents. It's plain markdown; any notes app opens it.
  - *"What if I lose it?"* — Any past session that emitted it has a copy in the chat history. Save the newest one.
  - *"Two businesses?"* — Two files. One file per business, always.
  - *"Can I edit it myself?"* — Yes, and your edits win. It's your file.
  - *"What about [session that doesn't exist yet]?"* — On the roadmap; the navigator will route you to the best available session today.

## After the session
- Send: the bundle ZIP again + the Quick Start HTML link + the one-line habit ("bring the file, save the copy").
- Track adoption via the assignment: session-log rows are the proof a member actually ran a session.

## Failure modes to watch in week one
- **Member doesn't save the updated file** → their next session interviews them again. Fix in office hours: find the last emitted copy in chat history, save it, move on.
- **Member pastes a deliverable INTO the file** ("I added my whole offer page") → remind: the file stores the distilled version; full documents live beside it, linked by name.
- **Member skips the navigator and runs a payoff session cold** → it will offer the provisional path; teach them to read the "provisional" flag as debt, not failure.
